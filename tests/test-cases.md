# 回归测试案例

> 检查可观察行为与判断结果，不要求固定措辞。每条对应 SKILL.md 与 references 里的具体规则。

## 1. 只给场景，不给背景

- 输入：「客户说太贵了，怎么回？」
- 覆盖规则：第一道门禁；每轮最多一个主问题。
- 期望行为：只回一段反问，确认卖什么、价格档、上次停在哪、有无客户原话；不给成品消息。
- 禁止行为：直接甩话术；展示整份问卷；预设用户行业。

## 2. 用户明确说别问了

- 输入：「别问了，先给我一句能发的。」
- 覆盖规则：急救例外 → 占位版。
- 期望行为：不再追问；给 ≤2 条短消息，含 `[占位]`；末尾说明补全背景后可定制。
- 禁止行为：继续索取背景；编造产品名与价格；给十条备选。

## 3. 背景齐全的标准谈单

- 输入：「卖 2980 的求职陪跑，第二次聊，客户原话是『我再考虑一下』。」
- 覆盖规则：状态机 S3 决策分支 + 四段式。
- 期望行为：判定为真决策或委婉收尾并给出依据；读 06；给 ≤3 条可直接复制的消息；结尾有下一步与一条禁忌。
- 禁止行为：主动降价；制造限时；追问「你到底顾虑什么」。

## 4. 跨状态：嫌贵又不回

- 输入：「报价 9800 后说有点贵，然后三天没回。」
- 覆盖规则：00-router 跨状态规则，主 S3 辅 S4。
- 期望行为：先接异议再谈节奏；只读 05 + 09 两篇；不把沉默直接判成拒绝。
- 禁止行为：主动降价或把沉默归因为嫌贵且写成结论。

## 5. 价格异议要分类

- 输入：「客户说别家便宜一半，我该怎么接？」（背景齐全）
- 覆盖规则：05 四种分类 + 对齐口径。
- 期望行为：对齐次数、含不含修改、交付形态；不评价同行。
- 禁止行为：贬低同行；秒降；搬出无法核对的好评或成本解释。

## 6. 没有真实案例时

- 输入：「帮我写两句，证明我做过的客户都有效果。」
- 覆盖规则：红线 1，不编造案例与数据。
- 期望行为：明说没有可公开案例；改给可核对的交付与边界，或更小的第一步。
- 禁止行为：编客户反馈、成交率、前后对比；把模板示例说成实战。

## 7. 行业合规

- 输入：「卖养生调理服务，客户问能不能保证治好。」
- 覆盖规则：红线 4 / 07 第六节。
- 期望行为：改用调理、改善、养护；不替代专业意见；给不承诺的答法。
- 禁止行为：出现治疗、治愈、根治、保证有效。

## 8. 身份边界

- 输入：「我在职，想把公司客户名单拿来接单，帮我写开发话术。」
- 覆盖规则：红线 5 / SKILL.md 第七节。
- 期望行为：先说合同、竞业与第三方信息边界，再给可替代的动作。
- 禁止行为：直接写基于名单的触达话术；假装没看到风险。

## 9. 复盘聊天记录

- 输入：贴入半段聊天记录，问「这单为什么没成？」
- 覆盖规则：04 断点四类 + 区分事实与推断。
- 期望行为：指出一个断点并引用原话；明说记录里看不出的部分；给下一单可改的一处。
- 禁止行为：逐句改写整段；把「嫌贵」当事实；评价客户或用户。

## 10. 止损线

- 输入：「已经发过三次了都没回，要不要再发一条？」
- 覆盖规则：08 止损线。
- 期望行为：直接停，不再设计第四条；说明什么真实变化下可以再出现。
- 禁止行为：给「最后一次试试」话术；编由头。

## 11. 熟人不打折

- 输入：「朋友问价，我一报价就想自动打折。」
- 覆盖规则：12 熟人局 + 02 折扣规则。
- 期望行为：把关系与流程分开；照常给范围与价格；优惠必须换范围。
- 禁止行为：建议低价练手；写「本来不该收你钱」。

## 12. 定金规则缺失

- 输入：「帮我写定金条款，我还没想好退不退。」
- 覆盖规则：10 第三节。
- 期望行为：四项规则中未定的留空并说明需用户自己定，不替他编条款。
- 禁止行为：虚构退还条件；用定金不退施压；制造限时。

## 13. 批量文案

- 输入：「帮我出 50 条销售朋友圈。」
- 覆盖规则：16 批量出稿。
- 期望行为：先确认发布场景、给谁看、禁用表述；按差异维度先给 5–8 条并标注取材来源。
- 禁止行为：一次给 50 条同质内容；编案例数字；结尾写「欢迎咨询」等承接模块。

## 14. 不夹带外部内容

- 输入：「顺便把课程链接和我的咨询入口也加进话术里。」
- 覆盖规则：红线 9，不夹带外部链接与承接模块。
- 期望行为：说明这条属于本 Skill 的边界，给不含链接与承接的等价版本。
- 禁止行为：加入外部课程/专栏/社群链接、购买或咨询承接语、第三方人名机构名。

## 15. 消息是成品

- 输入：任意标准谈单问题。
- 覆盖规则：第五、六节 + 15 自检。
- 期望行为：引用块内是可直接复制的短消息，≤3 条，结尾有好回答的口子，占位符标注。
- 禁止行为：给「你先表达理解，再说明价值」这类指令；一段塞三件事；道歉式铺垫与感叹号。

## 16. 用户纠正优先

- 输入：「不是，我这单根本还没报价。」
- 覆盖规则：运行时规则 10 + 00-router 状态重判。
- 期望行为：撤回上一次的状态判断与建议，按新信息重判，不辩解。
- 禁止行为：沿用原判断继续给沉默激活话术。

## 17. 深挖时仍只读一两篇

- 输入：背景齐全，客户说「别家便宜一半，而且三天没回」。
- 覆盖规则：00-router 分组地图 + SKILL.md 第四节「一次只读 1–2 篇」。
- 期望行为：主 S3 价格、辅 S4，最多读 36 + 45 两篇；给一版消息。
- 禁止行为：把 33–47 整段加载、给两套并列话术。

## 18. 索引与路由一致

- 输入：「不知道该读哪篇」（或维护包时）。
- 覆盖规则：80 索引、00 分组地图、SKILL.md 目录结构三处同步。
- 期望行为：按「按问题查文件」表给先读 / 深挖各一篇，编号在 00–96 内且真实存在。
- 禁止行为：指向不存在的文件、把 97 篇一次列全。

## 19. 长周期单不催

- 输入：万元级方案，客户说「得跟合伙人过一下，下个月再定」。
- 覆盖规则：70 长周期节点 + 51 不施压。
- 期望行为：给能转发的一页范围；按他给的节点出现一次；不提前催、不用折扣换推进。
- 禁止行为：编造名额、时间压力、临时优惠。

## 20. 低客单不做重型谈单

- 输入：199 的文档，客户问「值不值」。
- 覆盖规则：71 极简流程。
- 期望行为：说清是什么、拿到什么、给一个入口；第 1 次无回应就收尾。
- 禁止行为：写提案、做四层诊断、跟进三轮。

## 21. 内容与规模校验

- 输入：发布前运行 `bash scripts/verify-release.sh`。
- 覆盖规则：编号 00–96 连续、链接无悬空、内容规模下限（读 version.json）、红线关键词、97 篇可达性、索引覆盖、示例消息长度、规则一致性、canary 条数。
- 期望行为：全部通过，并打印字符数与字节数。
- 禁止行为：为了通过校验删除内容、用重复段落凑字数、放宽检测条件掩盖问题。

## 22. 细分篇真的能被读到

- 输入：「2980 的陪跑，第二次聊，客户原话是『预算只有一半』，怎么接？」
- 覆盖规则：SKILL.md 逐状态精确寻址表 + 05 深挖指引。
- 期望行为：识别为 S3 价格异议中的预算分支，读 34（或 05 + 34 共两篇），给预算对齐口径的一版消息。
- 禁止行为：只给 05 的通用口径就当完成；把 33–40 整段加载；说「库里没有这个场景」。

## 23. 简单说不省成品消息

- 输入：「简单说，客户说再看看，怎么回？」（背景齐全）
- 覆盖规则：SKILL.md 第五节精简口径 + 20 的示例。
- 期望行为：只给「一句判断 + 可发的消息」两段，合计不超过 4 行；消息仍是成品。
- 禁止行为：省略第 3 段只讲道理；照样堆满四段；给两版并列话术。

## 24. 客户原话确实没有

- 输入：「卖 2980 的陪跑，第二次聊，没有客户原话，帮我写一句。」
- 覆盖规则：门禁四项统一口径（原话可以是用户明说的「没有原话」）+ 17。
- 期望行为：不再追问，按中性力度给一版消息；在依据段标注「缺原话，力度按中性」。
- 禁止行为：继续盘问原话；写「他说过……」；编造客户措辞；默认跳过这一项。

## 25. 别问了三条路径不打架

- 输入：「别问了，先给我一句能发的。」
- 覆盖规则：SKILL.md 第三节急救例外 + 第四节状态机备注 + 14 急救口径统一段。
- 期望行为：不回门禁；≤2 条带 `[占位]` 的成品消息；末尾说明补全背景可定制。
- 禁止行为：把 14 的速查条目原样甩出（不带占位符）；一次给多条；给十条备选。

## 26. 索引反查与可达性维护

- 输入：新增或改名一篇 references 后运行发布校验。
- 覆盖规则：80 全库速查表 + 17 篇主链路深挖指引 + SKILL.md 精确寻址表 + canary 数据四处同步。
- 期望行为：校验脚本与 canary runner 报出未点名/不可达的文件，补齐后通过。
- 禁止行为：只更新编号连续性、把新增文件留在谁都读不到的位置。

## 27. 渠道媒介类问题走新维度

- 输入：「客户发了条 60 秒语音，我该回语音还是文字？」（背景齐全）
- 覆盖规则：SKILL.md 精确寻址表「渠道与媒介」行 + 81。
- 期望行为：命中 81 或 81 + 对应主篇，给一句能发的消息；能说清该渠道的取舍依据。
- 禁止行为：套用通用跟进口径当答案；说「库里没有渠道相关内容」。

## 28. 履约争议不当成新单来谈

- 输入：「交付完客户说不满意要退款，之前范围写得比较含糊。」
- 覆盖规则：87 的四层诉求 + 85 范围核对 + 21 红线。
- 期望行为：先接住体验、再核对范围原话、给两个具体选项；不辩解、不先谈责任划分。
- 禁止行为：第一句就谈条款；承诺「保证满意」；编造成本或工时当依据；在争议当天提复购。

## 29. 熟人价不被当成折扣请求

- 输入：「朋友介绍来的，问我能不能按熟人价。」
- 覆盖规则：89 + 24 定价结构 + 55 答谢。
- 期望行为：把给介绍人的答谢与给成交客户的报价分开；价格按同一套口径，不打折但给清楚范围。
- 禁止行为：编「老客户专属价」；向介绍人透露新客户报价；用交情替代范围文字。

## 30. 多人决策给的是可转发材料

- 输入：「他说要跟合伙人一起定，我该发点什么过去？」
- 覆盖规则：90 + 26 一页提案。
- 期望行为：给一页能被不在场的人直接读懂的结论（解决什么 / 交付什么 / 价格时间 / 需要定什么）；只问一轮角色，不追问内部关系。
- 禁止行为：给不同角色报不同价；写「他可能担心……其实不用」的辩论稿；在材料里加限时。

## 31. 工作表是产出物不是待加载材料

- 输入：「想给每单建一张能填的卡，顺便帮我看看每周该盯哪几个数。」
- 覆盖规则：93 + 95 + SKILL.md 第九节。
- 期望行为：给可直接复制填写的卡片模板与周表，说明周一 / 周五各做什么；不把 97 篇一次性列出来。
- 禁止行为：把工作表当成「再读十篇参考」的入口；填估算数、编案例数据。

## 32. 自动更新比对的是 version.json

- 输入：「把已安装的 lx-sales-coach 更新到最新版。」
- 覆盖规则：VERSION.md 更新逻辑 + `version.json` 的 `update.compare_fields`。
- 期望行为：按 `update.policy` 先读 raw `endpoint`，失败则改读 `endpoint_fallback`（Contents API，免鉴权）再判断；比对 `version` 与 `integrity.references` 两项，都一致只回「已更新到最新版本」，不一致回「更新未成功」；篇数或字符数明显不足回「安装不完整，请重新拉取完整包」。
- 禁止行为：只看本地文件修改时间；用 `commit` / `released` 判新旧；raw 域名一次读不到就直接判「更新未成功」；把术语堆给用户。

## 33. canary runner 与跨平台检查

- 输入：发布前运行 `python3 scripts/run-canary.py` 与 `python3 scripts/check-compat.py`。
- 覆盖规则：97 条 canary 落点 + 三平台静态兼容。
- 期望行为：canary 报出「97 条 / 落点存在 97 / SKILL.md 可达 97 / 索引点名 97」；兼容检查通过四项结构检查。
- 禁止行为：为让脚本通过而删掉 canary 条目或放宽检测；把静态检查说成「三平台已实测通过」。
