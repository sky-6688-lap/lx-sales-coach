# 发布前回归检查清单

> 每次改动 SKILL.md、references 或包级文件后逐项确认。`bash scripts/verify-release.sh` 覆盖其中的机械检查项，其余需人工过一遍。

## 一、结构（脚本检查）

- [ ] `SKILL.md` frontmatter 完整，`name` 与文件夹名一致，`description` 含触发词。
- [ ] 必需文件齐全：README / VERSION / CHANGELOG / LICENSE / agents-openai.yaml / tests / scripts。
- [ ] `references/` 共 81 篇，编号 00–80 连续，无缺号与重号。
- [ ] SKILL.md 的分组说明、00-router.md 的分组地图、80-glossary-and-index.md 的索引三处同步。
- [ ] 内容规模不低于 16 万字符 / 39 万字节（发布校验脚本检查）。
- [ ] 所有 markdown 相对链接目标存在，无悬空链接。
- [ ] 所有文件 UTF-8 编码、非空、无占位待写段落。

## 二、路由（人工）

- [ ] 状态机 S0–S9 判定顺序不冲突；跨状态规则仍取「更靠前会阻断推进的」。
- [ ] S3 三个分支（05/06/07）的边界清晰，价格与决策不被混为一谈。
- [ ] 路由表新增文件后，00-router 的文件地图同步更新。
- [ ] 一次只读 1–2 篇的原则没有被新规则破坏。

## 三、输出格式（人工 + 抽样）

- [ ] 四段式齐全：一句判断 / 依据与风险 / 可直接发的消息 / 下一步与一条禁忌。
- [ ] 引用块内是成品消息，≤3 条，每条一件事，占位符用 `[ ]`。
- [ ] 消息风格六条逐条成立，尤其「不道歉式铺垫、不用感叹号、不开放式盘问」。
- [ ] 案例段：无真实案例时明说，模板示例标注为非真实案例。

## 四、红线（人工 + 脚本关键词）

- [ ] 不编案例、数据、成交率、客户反馈。
- [ ] 不承诺结果、不夸大、不教逼单、不制造稀缺与虚假由头。
- [ ] 健康 / 教育 / 金融表述合规；持牌职业与在职竞业边界在位。
- [ ] 不出现第三方品牌、人名、机构名、社群名；不夹带外部课程、专栏链接与承接模块。
- [ ] 不使用未经授权的客户原话、截图、个人信息。

## 五、可安装性（人工）

- [ ] 文件夹名未改；若改名，SKILL.md 的 `name` 已同步。
- [ ] README 三种安装方式可照做；`scripts/install-local.sh` 不覆盖已有目录（除非显式 --force）。
- [ ] VERSION 与 CHANGELOG 版本一致；仓库未创建时不声称已发布。
- [ ] 在 WorkBuddy / Codex 里实际触发一次：用一个带完整背景的谈单问题，确认能自动加载并给出四段式结果。

## 六、版本记录

- [ ] 改动写入 CHANGELOG。
- [ ] VERSION 版本号递增，Released 时间与实际一致。
- [ ] 发布校验脚本通过后才打 tag 或推送。
