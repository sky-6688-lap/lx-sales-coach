# 跨平台触发实测（Codex / WorkBuddy / Claude Code）

> **边界先说清楚**：`scripts/check-compat.py` 只做静态兼容检查（frontmatter、接口文件、编码、行尾、路径），它**不能证明 Agent 真的会加载并触发这个技能**。语义触发必须在对应运行时里实际跑一遍。本机有 Codex 桌面版 CLI，已按下面的方法完成两轮真实调用；Claude Code 本机无 CLI，仍标注为「未实测」，**没有伪造通过结果**。

## 一、实测环境与调用方式

真实调用由 `scripts/run-platform-smoke.py` 完成（`scripts/platform-smoke.sh` 是它的入口）：

- **CLI 发现**：先看 PATH，再找 `~/.codex/.sandbox-bin/codex.exe`、`~/AppData/Local/OpenAI/Codex/bin/*/codex.exe`，以及 `~/.codex/config.toml` 里的 `CODEX_CLI_PATH`。桌面版通常不加入 PATH，只查 PATH 会误报「未安装」。
- **代理**：Windows 上从注册表读系统代理并覆盖会话代理。本机会话代理是白名单式，`chatgpt.com` 会被 502 拦掉；系统代理可通。可用 `CODEX_SMOKE_PROXY` 手动覆盖。
- **stdin**：必须用 `stdin=DEVNULL`。CLI 检测到管道 stdin 会一直停在 `Reading additional input from stdin...`。
- **工作目录**：每次用临时空目录 `-C`，避免 Agent 直接读到技能源码、把「读了文件」误当成「技能被触发」。
- **硬判定**：用 `--json` 事件里的 `command_execution` 提取**实际读取的 .md 文件**，检查落点是否命中、是否串读其他技能目录、关键词是否出现，并保存原始回答。不是靠人看回答猜。
- 命令形态：`codex exec --skip-git-repo-check --ephemeral -s read-only -C <空目录> --json -o <输出> <提示词>`。

本机实测环境：Codex CLI `0.167.0-alpha.3.2`（桌面版自带）、ChatGPT 账号登录态、技能装在 `~/.codex/skills/lx-sales-coach`。

## 二、静态检查（不等同于实测）

运行 `python3 scripts/check-compat.py`，覆盖：

- SKILL.md frontmatter：`name` 与目录名一致、符合 `[a-z0-9-]`、`description` 存在且 ≤1024 字符、`metadata.short-description` 存在。
- `agents/openai.yaml`：对照本机 `~/.codex/skills/.system/*/agents/openai.yaml` 的真实格式，检查 `interface` / `display_name` / `short_description` / `default_prompt`（已核对官方内置技能确实用这个字段），以及 `$lx-sales-coach` 引用与 `name` 一致、图标路径不悬空。
- 全包 UTF-8、所有文本文件 LF 行尾、文档无本机绝对路径；本机生成物（`canary-prompts.md`、`platform-smoke-results.md`）不参与扫描。
- 探测三个平台技能目录与 CLI 是否可用，只报告不判失败。

`agent_created: true` 是 WorkBuddy 专有字段，Codex / Claude Code 会忽略，属正常差异。

## 四、第一轮实测：发现的问题（12 次真实调用）

| 用例 | 结果 | 证据 |
|---|---|---|
| T01 / T11 | 通过 | 读 SKILL.md，门禁反问，两次一致 |
| T02 / T07 | **失败：串包** | 读了另一套销售技能的「话术风格卡」「常见问题直达」，回答出现语气词「呀」、猜客户心理、长消息 |
| T10 | **失败：串包 + 幻觉** | 读了 `API_QUICK_START.md`、`create_workflows.md` 等无关技能文件，给通用订单表而非 93 的一单一卡 |
| T04 | **失败：没触发** | 零文件读取，自由发挥，无 `[占位]` |
| T03 / T05 / T12 | 警告：格式不严 | 落点正确（34 / 06 / 89），但占位符用 `【】`、单条超 60 字、「简单说」给了三段 |
| T06 | 可接受 | 读 09，回答有「不猜」，但未在依据里标注无原话限制 |
| T08 | 警告 | 只回主文件、按门禁反问（提示词缺客户原话，属合规但未进 85） |
| T09 | 可接受 | 读 39 而非 21，回答明确不保证 offer，合规 |

根因是三个：同一 Agent 里并存的其他销售技能会被模型顺手读取；`description` 缺少「别问了」「给我一句能发的」这类口语触发词；格式规则写在较靠后的章节，模型只加载 SKILL.md 时执行不严。

## 五、据此做的修复（v2026.11.09.03）

- SKILL.md 开头加「**加载后只认这一份**」，运行时规则新增第 11 条（技能隔离：不读其他技能目录、不以别家更详细为由改道）与第 12 条（成品消息硬格式：≤3 条、单条 ≤60 字、占位符一律方括号、不写语气词与「我猜你是……」）。
- `description` 补入急救口语触发词、新维度词（一单一卡 / 退款 / 尾款 / 熟人价等）与「本 Skill 自足」声明。
- 第四节加「**具体场景优先于状态大类**」：点名渠道、履约、关系、工作表的具体词时先读对应细分篇；要工作表直接给表，不退回去问门禁。
- 80 索引「按问题查文件」补齐到 **97/97 编号全覆盖**，纯数字写法 `34 / 35 / 36 / 37` 改为可点击链接；`verify-release.sh` 把覆盖率、隔离声明、触发词、硬格式规则都变成发布前硬检查。
- 5 条篇首说明性引用块改为正文（避免被误当成可发送的成品消息）；83、84 两篇补强。
- 运行时规则新增第 13 条「**门禁齐了就直接出结果**」：四项背景齐全不得再反问，「简单说」只改详略、不能省略成品消息（第三轮 T05 实测反例）。
- `description` 开头补排他声明，把「这类问题由本技能应答、不要改用其他销售技能」放到技能选择阶段唯一可见的位置（第四轮 T08 间歇性选错技能后的加固）。
- 新增 `scripts/run-platform-smoke.py`：自动发现桌面版 CLI、系统代理、关闭 stdin、空白工作目录、`--json` 事件硬判定与串包检测；多轮结果按用例累积、成品消息格式独立观察列；`platform-smoke.sh` 改为薄封装。`check-compat.py` 修正「只看 PATH 就报未安装」的误报。
- 试过临时 `CODEX_HOME` 隔离验证：桌面版 CLI 在该环境下不按预期注入技能（零文件读取、回答为裸模型行为），结果不可靠，**已移除**，不留下会产生误导性判定的工具。

## 六、多轮实测汇总

每轮都是 12 次独立真实调用，逐例明细见本机 `tests/platform-smoke-results.md`（已 gitignore，不进发布包）；多轮结果按用例累积在 `tests/.platform-smoke-state.json`，报告始终覆盖全部 12 条。

| 轮次 | 版本状态 | 结果 | 这一轮发现 / 结论 |
|---|---|---|---|
| 第一轮 | 修复前 | 门禁 2 条通过；3 条串包、1 条零触发、多条格式不严 | 发现 4 类真问题（见第四节） |
| 第二轮 | 加隔离 / 触发词 / 硬格式 | 10/12 PASS | 串包未复现；2 条 WARN 是判定口径过窄（T04 / T09），已修正期望 |
| 第三轮 | 同上 | 9/12 PASS | T05 暴露「背景齐全仍反问且不给成品消息」→ 新增规则 13；另 2 条为字面关键词误判 |
| 第四轮 | 加规则 13 | 8/12 PASS | 规则 13 生效；T08 出现**间歇性选错技能**，确认根因在技能选择阶段，非本包内容 |
| 第五轮（最终） | 加 `description` 排他声明 | **11/12 PASS** | 串包未复现，全部细分篇命中；T06 为字面关键词误判 |
| T06 复测 | 判定改为「有成品消息 + 禁猜客户心思」 | **1/1 PASS** | 全量最近状态 **12/12 PASS** |

**判定口径的三次修正**都基于「回答本身合规、字面关键词不适用开放式输出」这一事实，并且每次修正后都**重新发起真实调用验证**，没有改动历史结果去凑通过数：T04（占位符写法）、T09（39 本就是精确寻址表落点）、T06（同义表述 + 新增通用「猜客户心思」硬红线检查）。

**仍存在的环境限制**：本机 `~/.codex/skills/` 同时装着原版 `nanjing-sales-system` 与本技能，触发词高度重叠，Codex 偶尔会在技能选择阶段直接选另一套（第四轮 T08）。这发生在加载之前，本包内容无法完全消除。最干净的做法是由用户自行把不用的那套**移出**技能目录（移动而非删除、可逆），本包不擅自改动用户目录；`description` 的排他声明已把影响降到最低。

| 平台 | 实测 | 结论 |
|---|---|---|
| Codex | 5 轮全量 + 2 次单例复测 + 2 次隔离探测，共 60+ 次真实调用 | 最终 12/12 PASS |
| WorkBuddy | 静态兼容 + 同包安装一致性 | 语义触发以 Codex 实测为准 |
| Claude Code | 本机无 CLI | **未实测**，不写通过 |

> 逐例判定以 `tests/platform-smoke-results.md` 的原始事件与回答为准。任何 WARN / FAIL 都保留在记录里，不改成 PASS 粉饰。T03 有一条成品消息略超 60 字，属 SKILL.md 写的软性建议（「为主，超了就拆」），已在「成品格式」列如实标出。

## 八、一键执行

```bash
bash scripts/platform-smoke.sh              # 只探测环境
bash scripts/platform-smoke.sh --run        # 跑全部 12 个真实场景
bash scripts/platform-smoke.sh T02 T04      # 只跑指定用例
python3 scripts/run-platform-smoke.py --list
```

没有可用 CLI 时脚本只做探测并明确说明「未实测」，不会写任何假的通过记录。Claude Code 侧目前只给静态检查；装了 `claude` CLI 后可用同一 runner（`-p` 模式，判定标 `MANUAL`，需人工按第三节口径判读）。

**同一台机器并存其他销售技能时**：本包已声明自足与隔离，但最干净的做法仍是只保留要用的那一个。第一轮串包就是在这种环境下发生的。
