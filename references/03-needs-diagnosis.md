# 03 需求诊断：从「他说的事」到「他真正要买的」

> 状态 S1：聊过，但没确认他真正想解决什么、以及不解决会怎样。也用于「不会提问」「聊完还是不知道怎么接」。

## 一、诊断不是多问，是问到那一层

很多人把「了解需求」做成问卷，连着问五六个问题，对方越答越累。有效路径只有四层，一层一层往下，**每层最多一个问题**，拿到就往下走：

| 层 | 要拿到的 | 可以这样问 |
|---|---|---|
| 1 现状 | 他现在具体是怎么做的 | 「你现在这块是自己弄，还是有人帮着？」 |
| 2 试过什么 | 已经付出过的努力 | 「之前试过什么办法吗？」 |
| 3 卡点 | 他自己认为卡在哪 | 「你觉得主要卡在哪一步？」 |
| 4 代价 | 不改会继续耗掉什么 | 「如果先不动，接下来这阵会怎么样？」 |

第 4 层最关键，也最常被跳过。**没有代价就没有购买理由**；但代价必须由他自己说出来，不能由你替他渲染（「再拖下去就晚了」属于制造焦虑，红线）。

四层不必全走完。他一开口就说「下个月要交，现在还没头绪」，第 1、4 层已经给了，直接从第 3 层接。

## 二、先接住，再问

每个问题前先复述他刚说的那句，用他的词。这不是客套，是让对方确认你听懂了，也避免你按自己的经验跑偏。

- 差的写法：「为了更准确地帮到你，想了解几个问题：1…2…3…」
- 好的写法：「你说改了三版还是没回音——是投出去没回音，还是自己改着改着就卡住了？」

后者只问一件事，而且给了两个具体选项，对方一句话就能回。

## 三、三类伪需求

不是每个来问的人都在买。尽早分辨，能省下大量跟进时间：

| 类型 | 识别信号 | 处理 |
|---|---|---|
| **学习欲** | 问「你怎么做的」「能不能讲讲思路」，但不说自己的处境 | 正常聊一两句，不进入报价；给一个可自己动手的入口 |
| **比价** | 上来问价、问包含什么、拿别家条款逐条对，不谈自己的事 | 回一句范围确认（见 02），不陪着逐条比 |
| **替别人问** | 「我朋友想…」「我们领导让了解一下」 | 问一句「这事儿最后是你要用，还是得跟对方确认？」，据此决定要不要继续深聊 |

伪需求不等于拒绝，也不必点破。只是**别按真需求的力度投入**：不写方案、不做诊断、不排进跟进表。

## 四、需求确认句：把对话收口

聊到差不多时，用一句把理解复述回去，让对方确认或纠正。这句是后面所有报价、提案的地基：

> 我理一下：你最想解决的是 [用他的词]，之前试过 [他说过的办法] 没成，卡在 [卡点]。
>
> 这次先不动的话，[他自己说的代价]。我理解得对吗？

对方说「对」→ 进 S2 报价节点。
对方纠正 → 按他改的重写一遍，不要辩解。
对方说「也不完全是」→ 只追问一个点：「哪块我说偏了？」

**不要用**「所以你需要的就是我们的 XX 服务」把确认句变成推销，那一句会让前面建立的理解全部作废。

## 五、把聊天变成资产：诊断记录四格

每次谈完随手记四格，[04-chat-review.md](04-chat-review.md) 的复盘和后续跟进都靠它：

```
现状：
试过：
卡点 / 代价：
他的原话（1–2 句）：
```

只记他说的，不记你的判断。判断写在另一栏，并标明是推断。这样换时间再来跟，不会把「我猜他嫌贵」当成事实。

## 六、常见错误

- **连环问**：一次发三四个问题，对方通常只回最后一个。
- **用专业词替他总结**：他一听到术语就不好纠正你，误判被固化。
- **急着给方案**：需求没确认就讲「我可以帮你做 A、B、C」，后面只能靠打折收场。
- **把抱怨当需求**：「现在行情差」是情绪，不是这次要买的东西。
- **替他制造代价**：红线。

## 七、禁忌

这一层最忌讳**把诊断做成审问**。判断做对了的标志，是对方愿意主动多说一句自己的情况；如果他的回复越来越短，通常说明问题太抽象或太多，退回上一层，用一个二选一的问题重新开口。
