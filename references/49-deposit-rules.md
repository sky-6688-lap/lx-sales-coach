# 49 定金：四要素、规则未定与分阶段收款

> 补 [10-close-and-deposit.md](10-close-and-deposit.md) 第三节。定金的作用是让双方把时间确定下来，不是把对方锁住。

## 一、四要素（缺一不可）

1. **金额或比例**
2. **抵不抵后续费用、怎么抵**
3. **什么情况可退、什么情况不退**（按用户真实规则写）
4. **付了之后下一步是什么**（排期、材料、第一次时间）

**模板示例（非真实案例）**
> 开始时间要留的话，先付 [金额] 定金，这部分直接抵在总价里。
> 后面如果 [用户规则里的情形 A]，这部分可以退；[情形 B] 就不退了，我提前说清楚。
> 付完我把排期和材料清单发你，我们 [时间] 开始。
> 这版规则你看没问题的话，我把收款方式发你？

## 二、用户没定规则时怎么办

**不要替他编一套看起来很严的条款**。这是最容易踩的坑：Agent 顺手写出「定金一经支付概不退还」，用户并未定过这条，发出去就是自己给自己挖坑。

三种可选做法，按用户真实情况选：

| 情况 | 做法 |
|---|---|
| 用户有明确规则 | 逐条写进消息，不加工、不加重 |
| 用户只有大致想法 | 把不确定的部分留 `[占位]`，并说明「这块按你定的规则补」 |
| 用户完全没想过 | 建议先不收定金，用一次正式确认 + 排期代替 |

**降级版收口**：
> 开始时间要留的话，我们先把 [日期] 定下来。
> 定金这块你还没定规则，这次就不走了；我把范围和材料清单发你，到时候直接开始。

## 三、分阶段收款

万元级常用，比一次性收全款更容易让双方核对：

```
第一段：确认范围 → 付第一段 → 交付第一段的验收项
第二段：确认第一段结果 → 再报第二段 → 付第二段
```

要点：每段的范围与价格绑在一起（见 26 模板 B），不写「后面再说」；第二段不是自动生效，需要一次确认。

## 四、八个场景

| # | 场景 | 处理 |
|---|---|---|
| 1 | 「能不能先不付定金」 | 可以，用排期 + 范围确认替代，不施压 |
| 2 | 「定金能少点吗」 | 按用户规则；没规则就说明需要他定，不现场编 |
| 3 | 「付了之后能退吗」 | 如实按规则答；规则没有就直说还没定，先别收 |
| 4 | 「能不能做完再付」 | 按用户真实规则；不为了成交临时改规则 |
| 5 | 「先付一半行不行」 | 同上，付款方式属于用户的经营规则 |
| 6 | 「我这边要走对公流程」 | 给一页范围与报价信息，方便他走流程，不催 |
| 7 | 熟人局，不好提定金 | 见 57，把关系与流程分开说 |
| 8 | 对方付了但迟迟不发材料 | 提醒一次材料与时间，不反复催、不暗示违约 |

## 五、禁止清单

- 「今天付才有这个价」「就差最后一个名额」「不定就被别人占了」。
- 用「定金不退」去吓人：规则要写清，但不拿来施压。
- 假装已有他人下单、假装排期快满。
- 用户没定规则却替他写「概不退还」。
- 收完定金又追加新费用。

## 六、常见错误

- 条款含糊（「先付一点意思一下」），后面必然扯皮。
- 只在消息里口头说规则，不落成一页范围。
- 把退款条件写成单方面有利，交付期反而更难沟通。
- 收口时把定金和优惠绑在一起（「现在付减 X」）。

## 七、禁忌

最忌讳**把定金当成逼定工具**。判断做对了的标志：对方清楚知道「付了之后会发生什么、什么情况下能退」，且这些规则确实是用户自己定的。
