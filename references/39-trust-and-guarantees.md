# 39 信任类：要保证、要案例、要方案、没做过我这种

> 补 [07-objection-trust.md](07-objection-trust.md)。总原则：能降低风险的只有可核对的事实和更小的第一次，不是更响的保证。

## 一、四类问法与去向

| 他问 | 真正在问 | 动作 |
|---|---|---|
| 「能保证效果吗」 | 结果不确定时谁承担 | 不承诺，说清可控制与需配合的两块 |
| 「有没有做过我这种」 | 经验是否可迁移 | 如实说，按三种情况答 |
| 「给我个案例 / 好评」 | 想要可核对的证据 | 有授权才用；没有就明说没有 |
| 「先出个方案我看看」 | 想零成本看到成品 | 给一页范围，不给成品方案 |

## 二、「能保证吗」：把判断拆成两块

> 这个担心是对的，我不说包结果的话。
> 我这边能确定的是：会给你 [交付物]，过程里 [具体动作]，做完你能拿到可以直接用的东西。
> 需要你配合的是 [材料 / 时间]，这部分不到位，进度会受影响。
> 要不先按 [更小的第一步] 试一次，做完你看东西再决定要不要往下走？

**两块**：你能控制的（交付、过程），和需要双方配合的（材料、投入、外部环节）。第三句是关键——说清不确定性，比抹掉不确定性更让人放心。

**不要**：「肯定没问题」「不满意全额退」（用户没定过这条规则）、「这样做一般都能成」。

## 三、「做过我这种吗」：三种如实答法

| 真实情况 | 答法 |
|---|---|
| 做过类似的 | 说一条最相关的，只说事实与结果形态，不报数字、不报客户身份 |
| 做过相邻但不完全一样 | 「相近的是 [什么]，和你这次不一样在 [哪]，所以我先按你的情况对一遍范围」 |
| 没做过 | 直说没有，把可核对的部分给足：做法、交付物、边界、小第一步 |

**不要**：「很多客户都…」「大家都说…」「类似案例特别多」。无法核对的模糊背书，比坦白说没有更伤信任。

## 四、「给我个案例」：授权优先

可使用的前提（见 56）：

1. 对方明确许可以什么形式使用（匿名 / 截图 / 使用范围）。
2. 去掉姓名、公司、联系方式、金额等可识别信息。
3. 不加工成夸大结论，不补数字。

**没有可用素材时**：

> 这类情况我这边没有可以公开的例子。
> 你可以先把你的具体情况发我，我按范围说清楚会怎么做、会给你什么。
> 要不先按 [小第一步] 走一次，做完你看东西再决定。

不拿模板示例冒充实战，不拿别人的截图充当自己的。

## 五、「先出个方案」：给范围页，不给成品

成品方案本身就是交付物。给一页范围（做什么、交付什么、时间、不包含什么、费用、下一步）即可，见 [26-proposal-templates.md](26-proposal-templates.md)。

> 我可以先给你一页范围，写清做什么、交付什么、时间、不包含什么。
> 完整方案就是正式交付的那部分了。
> 你先看这页对不对得上，要不要我发你？

## 六、行业与身份边界（这一段不能省）

用户卖的东西涉及健康、教育、金融、法律时，信任类异议最容易诱发违规承诺：

- 健康：不说治疗 / 治愈 / 根治，用调理 / 改善 / 养护，不替代专业意见。
- 教育：不写包过 / 保证提分 / 保 offer。
- 金融：不写收益 / 稳赚 / 代客操作。
- 持牌职业、在职人员、第三方信息：先说边界（见 [21-boundaries-and-compliance.md](21-boundaries-and-compliance.md)），再给动作。

用户明确提供的资质可如实转述，不替他补没提过的资质。

## 七、六个常见错误

- 用更响的保证消除担心。
- 编案例、编反馈、编成交数据。
- 把「别家都说能保证」当作自己也要跟的理由。
- 一次性发一大堆材料，让对方自己找可信的部分。
- 用户没定退款规则，却替他写进消息。
- 用「我理解你的担心」连着三段共情，却没给任何可核对的事实。

## 八、禁忌

最忌讳**把不确定性全抹掉**。用户真的会把这些话发出去；任何一句「肯定没问题」，都会在交付期变成更大的矛盾。
