# 00 总路由：先判状态，再动手

> 状态判不准、问题跨了好几层、或不确定该读哪篇时，读这一篇。其余时候直接按 SKILL.md 的路由表进对应文件，不用回来。

## 一、这份文件解决什么

用户描述的是**感受**（「客户不理我」「感觉要黄」「不知道该不该再发」），而动作取决于**状态**（对方那头到底发生了什么）。把感受翻译成状态，是这份 Skill 的第一步，也是最容易做错的一步。

同一个「不回消息」，可能是价值根本没说清（S0）、报价太早（S2）、有异议没说出口（S3）、纯粹在忙（S4）。四种情况的下一句完全不同。判错了，话术再漂亮也发不出去。

## 二、状态判定顺序

按下面顺序问自己，命中即停，不要再往下追：

1. **对方有没有明确表达过阻力？**（说过贵、要考虑、对比、问家人、怕没效果）→ S3，进 05 / 06 / 07。
2. **是不是报过价之后才没下文的？**→ S4，进 09；若中间还夹着异议，主状态仍取 S3。
3. **意向是不是已经明确，只差一个动作？**（约时间、确认范围、付定金）→ S5，进 10。
4. **已经付钱了吗？**→ S6，进 11。
5. **有没有报过价？** 没报过且正在犹豫该不该报 → S2，进 02。
6. **有没有确认过他真正想解决的事？** 没有 → S1，进 03。
7. **他知不知道你能帮他做成什么？** 不确认 → S0，进 01。
8. **卡点是用户自己的状态或经营问题？**（不敢收钱、被拒绝、时间乱、没咨询量）→ S7，进 12 / 13。
9. 用户只要一句能发的 → S8，进 14；要出内容 → S9，进 16；要复盘记录 → 04。

## 三、深浅判断

| 用户想要 | 给什么 |
|---|---|
| 一句能立刻发的 | 14 的标准口径，或占位版；不展开方法论 |
| 想知道为什么、想有多种打法 | 直接进对应模块，先给一句短的再展开 |
| 两边都要 | 先给可直接发的消息，再给 2–3 条依据 |
| 要复盘一整段聊天 | 04，按时间线找断点，不逐句改写成话术 |

用户说「简单说」就别给四段式的完整版；四段式是默认结构，不是必须堆满的模板。

## 四、跨状态与误判

- **嫌贵 + 不回**：主 S3（异议没接住是因），辅 S4。先把异议那句接稳，再谈节奏。
- **一直免费问、不下单**：不是 S3 异议，是 S0/S1 没建立付费边界，读 01 与 07 的「只想白问」段。
- **聊得很好但就是不定**：多半是 S5 缺一个具体动作，不是信任问题；别急着加案例、加保证。
- **用户说「客户没回复我」但没说报没报价**：这属于门禁缺项，先问关系进度，不要凭经验猜。
- **把「忙」判成「拒绝」**：S4 的头三次触达都按「对方在忙」处理，语气不带委屈、不追问原因。

## 五、每次回答前的六秒自检

1. 三件事 + 原话齐了吗？不齐 → 门禁或占位版。
2. 状态判的是**对方**那头发生的事，还是用户自己的焦虑？
3. 这次只读了 1–2 篇吗？
4. 消息是成品吗？能不能直接复制？占位符标了吗？
5. 有没有偷用长期记忆、编案例、预设行业？
6. 结尾给的是「下一步 + 一条禁忌」，还是又甩了一堆备选？

## 八、一条总原则

**宁可少给一招，也别给一版发不出去的话。** 用户拿着成品消息是要真发的，任何一处需要他再改一遍才能用，都算这次没做完。
