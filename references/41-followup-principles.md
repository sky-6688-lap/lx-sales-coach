# 41 跟进的第一原则：每次带一样新东西

> 补 [08-follow-up-rhythm.md](08-follow-up-rhythm.md)。这一篇只讲「什么算值得发的跟进」，节奏表在 42，消息在 46。

## 一、一句话判断要不要发

> 这条消息里，有没有一样他上次没见过的、对他有用的东西？

有就发，没有就不发，等有了再发。「考虑得怎么样了」「上次那版看了吗」都没有新东西，对方只能回「还在看」，对话没有增加任何信息。

## 二、四类可以带的新东西

| 类型 | 具体形态 | 注意 |
|---|---|---|
| **一条针对他处境的信息** | 他提过的那件事，你后来想到的一点 | 必须是真的、具体的、不推销的 |
| **一个范围上的新选项** | 更小 / 更晚 / 拆开做 / 分阶段 | 选项必须来自用户真实可提供的范围，不能凭空造低价版 |
| **一个他问过的问题的答案** | 补上当时没答全的那一处 | 只补那一处，不复习全部内容 |
| **一个真实存在的时间节点** | 他提过的节点、你这边范围确实变了 | 由头必须真实，编出来的属于红线 |

**反例（都不算新东西）**：节日祝福、群发问候、「刚好想起你」、把上次的话换几个词再说一遍、转发一篇通用干货。

## 三、三个「真实由头」的判据

1. 来自记录：能在诊断四格或跟进三格里指出是哪句原话。
2. 可核对：对方看到能认出「对，我说过这个」。
3. 不依赖巧合：不是「刚好有个名额」「今天最后一天」这类编排。

「刚好想起你」不算由头，因为它无法核对，也不需要任何真实事件就能写出来。

## 四、跟进消息的三条硬约束

1. **不要求他解释**：不问为什么没回、不问考虑得怎么样。
2. **不要求他做大决定**：给一个能一句话回的小问题，或干脆写「不用回我」。
3. **不带情绪**：不委屈、不试探、不暗示自己等了很久。

**模板示例（非真实案例）**
> 上次你说 [他的原话]，我后来想到一点：[一条具体、能自己用的信息]。
> 你先看着，不用回我。

注意「想到一点」后面**不能**接「所以我们这个服务正好能…」——那就成了伪装成关心的催单。

## 五、跟进前的三格检查

```
上次停在哪句（他的原话）：
已经给过什么（别重复）：
这一条的新东西是什么：
```

第三格填不出来，就别发。这三格见 [30-diagnosis-records.md](30-diagnosis-records.md)。

## 六、跟进与状态的关系

跟进不是独立模块，它是**在某个状态上继续提供判断依据**：

| 状态 | 跟进该带什么 |
|---|---|
| S3 异议未解 | 一个更小的选择，不是重提异议 |
| S4 沉默 | 一条对多种归因都成立的信息 |
| S5 缺动作 | 一个带时间的具体动作（其实该走 48，不是跟进） |
| S6 已成交 | 交付节点，不是追单节奏 |

把 S5 当 S4 处理，会一直「跟进」一个其实只差一句收口的单子；把 S6 当 S4，会对已成交客户发追单消息。先回 [00-router.md](00-router.md) 判状态。

## 七、常见错误

- 把跟进做成每日打卡。
- 每次换着花样问同一个问题。
- 用「不打扰了哈」开头，然后连发三条。
- 把沉默当成嫌贵，跟进里主动降价。
- 三条跟进内容互相重复，因为没看「已经给过什么」。

## 八、禁忌

最忌讳**在没有新东西的时候出现**。跟进次数越多，前面所有消息的语气越像施压；宁可少发一条，也别让对方觉得需要躲着你。
