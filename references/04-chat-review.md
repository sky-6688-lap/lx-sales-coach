# 04 聊天记录复盘：找断点，不改作文

> 用户贴了一段聊天记录、问「这单为什么没成」「帮我看看哪句说错了」时读这一篇。

## 一、复盘的目标

不是把每句话改得更漂亮，而是找到**对话从哪一步开始不再往前走**。多数单子不是被一句话说砸的，是某一处该收口没收、该确认没确认，之后双方都在礼貌地拖。

产出固定三块：断点在哪一步、依据（引用记录里的原话）、下次这一处换成什么动作。

## 二、按时间线找四类断点

顺读一遍记录，标出这四类位置，命中第一个就先讲它：

| 断点 | 记录里的样子 | 对应状态 |
|---|---|---|
| **A 价值没落地** | 你发了一长段介绍，对方回「好的，我了解一下」「挺厉害的」 | S0 → [01-value-and-positioning.md](01-value-and-positioning.md) |
| **B 需求没确认** | 你连续提问或连续给方案，但没出现一句「是这个意思吗」的收口 | S1 → [03-needs-diagnosis.md](03-needs-diagnosis.md) |
| **C 报价孤零零** | 只有一个数字，没有「做什么 / 交付什么 / 下一步」，或报完立刻补了大段解释 | S2 → [02-pricing-and-quote.md](02-pricing-and-quote.md) |
| **D 异议没接住 / 没有下一步** | 对方说「考虑一下」「有点贵」，你回「好的」「随时找我」，之后就没了 | S3 或 S5 → 05 / 06 / [10-close-and-deposit.md](10-close-and-deposit.md) |

**看信号，不看字数**：一方连续发 3 条以上、另一方只回 2–6 个字，通常上一次收口就失败了；对话结束在「好的」「我看看」「有需要找你」这类句子上，说明最后缺一个具体的下一步。

## 三、复盘表（输出格式）

```
断点：[A/B/C/D]，在第 X 轮
依据：「引用记录里的原话」
发生了什么：[一句话，用记录里的事实，不评价人]
下次换成的动作：[一个动作 + 一句可发的话]
无法判断的部分：[记录里没出现的信息，明说]
```

最后一块必须有。记录里没出现价格、没出现客户原话、或只贴了半段，就直说「这段看不出他卡在钱还是卡在不确定」，**不要靠猜补齐**。这是红线 6 与「不编造」在复盘场景的具体要求。

## 四、区分事实与推断

复盘里最容易出错的是把推断写成结论：

- 事实：「他报价后两天没回」
- 推断：「他嫌贵」（可能是在忙、在等家人、在比价、根本没看到）

写法是「推测可能是 X，依据是他之前说过 [原话]；也可能是 Y，记录里看不出来」。给动作时选**对两种可能都成立**的那一句，别押宝在单一归因上。

## 五、不要做的事

- **不逐句改写整段聊天**：那会产出一大堆用不上的话术，用户下次也复现不了。
- **不评价客户**：不写「这客户没诚意」「白嫖型」。可以写「记录里没有出现过他自己的处境，无法判断意向」。
- **不评价用户**：不写「你太急了」「太怂」。只描述动作和后果。
- **不把复盘变成逼单教学**：不教「下次就该制造点紧迫感」。
- **不使用记录里的第三方个人信息**：如果贴入内容含有他人的姓名、公司、联系方式，复述时一律略去，只保留与判断有关的事实。

## 六、复盘之后

给完断点，附一个「下一单可以先用起来的一句」，通常就是需求确认句（见 03）或带下一步的报价三件套（见 02）。不要一次给三条改进项，一次只改一个断点，改完看下一次聊天的信号。
