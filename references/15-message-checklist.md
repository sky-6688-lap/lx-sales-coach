# 15 发送前自检清单与场景替换表

> 任何一段对外消息输出前，都要过这一篇。这是最后一道关，不是可选步骤。

## 一、十二条自检

打勾才算成品，任何一项不通过就改，不要把「差不多能用」的消息交出去。

- [ ] **门禁**：三件事 + 一句客户原话齐了？没齐就走门禁或占位版。
- [ ] **状态**：这条消息对应的是哪个状态？和判断里写的一致吗？
- [ ] **只做一件事**：每条消息只有一个目的，连发不超过 3 条。
- [ ] **能直接复制**：没有旁白、没有解释、没有「你可以先…再…」这种指令。
- [ ] **用他的词**：产品名、价格、客户称呼、处境描述都沿用用户原词。
- [ ] **占位符**：缺的信息用 `[占位]` 标出，没有替用户编产品、价格、时间、规则。
- [ ] **好回答的口子**：结尾是是/否、二选一或一个具体小动作，不是开放式盘问。
- [ ] **语气**：没有道歉式铺垫、没有连环追问、没有感叹号、没有「您」堆叠的客套。
- [ ] **长度**：单条以 60 字以内为主，超了就拆。
- [ ] **不施压**：没有限时、名额、涨价预告、暗示已有人下单、替客户做决定。
- [ ] **不承诺**：没有保证、一定、包过、根治、稳赚，没有编造的案例或数字。
- [ ] **合规与归属**：行业表述过了一遍；没有外部链接、承接模块、第三方人名或机构名。

## 二、场景替换表

输出占位版后，用用户提供的原词逐格替换。替换不是可选项：

| 占位符 | 换成什么 | 换错的样子 |
|---|---|---|
| `[产品]` / `[范围]` | 用户说的具体交付，不是品类泛称 | 「您的服务」「相关方案」 |
| `[价格]` | 用户给的数字或价格档 | 自己估算一个数 |
| `[他的原话]` | 贴入的原话，可截取但不能改写意思 | 改写成更礼貌的版本 |
| `[交付物]` | 能拿到手的具体东西 | 「一套方法论」「完整支持」 |
| `[时间]` | 他提过的时间点，或用户自己定的真实排期 | 「近期」「尽快」 |
| `[材料]` | 真实需要对方准备的东西 | 编一个不存在的前置条件 |
| `[金额]` / 定金规则 | 用户确认过的规则；没定就留空并说明 | 替他编退还条款 |

**一条硬规则**：如果替换完发现有一格填不上，说明信息还缺。此时不要硬凑，把缺的那一格写进四段式的「下一步」，让用户补。

## 三、四个不合格样例与改法

**1 指令式，不是成品**
- ✗ 「你先表达理解，再说明这次的范围，最后约个时间。」
- ✓ 「范围我按 [范围] 定，交付 [东西]。[周四 / 周五]，哪个方便？」

**2 一段塞三件事**
- ✗ 「不好意思打扰了！上次那版您看了吗？如果预算有问题我们这边也可以再商量一下，这周定下来的话还能按原价走～」
- ✓ 拆成一条只确认范围的消息，删掉打扰、预算猜测、限时。

**3 要求对方解释**
- ✗ 「是不是我哪里没说清楚，你怎么一直没回呀？」
- ✓ 「上次你说到 [原话]，这块我补一句：[具体信息]。用得上先看着，不用回我。」

**4 把推断写成事实**
- ✗ 「你应该是觉得价格超预算了吧，我可以给你少一点。」
- ✓ 「你说贵，是这次预算上不方便，还是想先确认做出来是什么样？」

## 四、四段式的最后一段也要过检

「下一步」必须写**发出去之后看什么信号**（他有没有回答那个具体问题、有没有问范围/时间/钱），不是「持续跟进」这种空话；「一条禁忌」只写这个场景最容易犯的那一件，不列一串通用注意事项。

## 五、批量出稿时

一次给多条消息或文案时，逐条过前六项，另外检查：条目之间是否有真实差异（不是同一句换几个词）、是否用了不同客户的同一句原话、有没有把模板示例当真实案例。
