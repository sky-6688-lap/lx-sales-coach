# 30 四张记录表：把聊天变成资产

> 补 [03-needs-diagnosis.md](03-needs-diagnosis.md) 第五节、[04-chat-review.md](04-chat-review.md) 与 [08-follow-up-rhythm.md](08-follow-up-rhythm.md)。表格是给用户自己记的，不要求 Agent 持久化任何信息。

## 一、为什么只记原话

隔一周再来跟，最容易被自己的记忆骗：「我记得他嫌贵」——其实他只说过「我再看看」。记录里把**事实**和**推断**分两栏，下次就不用靠猜，也不会把推测当成状态结论。

四张表都遵守三条：只记用户提供的信息；不记第三方身份信息；推断单独标注。

---

## 二、表 1｜诊断四格（每单一张）

```
现状（他的原话）：
试过什么（他的原话）：
卡点 / 代价（他的原话）：
客户原话 1–2 句（逐字）：

我的推断（标注为推断）：
  可能是 [X]，依据 [哪句]
  也可能是 [Y]，记录里看不出
```

**填写示例（模板示例，非真实案例）**
```
现状：「投了十几份，一个回音都没有」
试过什么：「自己改了三版，主要换了排版」
卡点 / 代价：「不知道该动哪儿；下个月有个想投的岗位」
原话：「我再考虑一下」

推断：可能是需要时间确认（依据：提过下个月的节点）；
      也可能在比价（记录里没出现过价格相关的话，看不出）
```

## 三、表 2｜跟进三格（每次触达前看）

```
上次停在哪句（他的原话）：
已经给过什么（避免重复）：
下一次的真实由头 / 时间：
```

第二格是核心。重复发同一类内容，是让对方从「在忙」变成「不想回」的最快方式。由头必须是真实存在的：他提过的节点、他做过的事有新进展、你这边范围真的变了。**编出来的由头属于红线**。

## 四、表 3｜单子复盘表（每周挑一单）

```
断点：[A 价值没落地 / B 需求没确认 / C 报价孤零零 / D 异议没接住或缺下一步]
在第几轮：
依据（引用记录原话）：
发生了什么（只写事实）：
下次换成的一个动作：
无法判断的部分（记录里没出现的）：
```

每周只挑一单、只改一处。改完整周都按这一处练，别一次列五条改进项。

## 五、表 4｜周经营表（给自己看）

```
本周 A 类（处境+路径都清楚）：__ 单 → 排在谈单块
本周 B 类（处境清楚、路径不清）：__ 单 → 一次确认路径后低频
本周 C 类（两项都不清）：__ 单 → 只回一两句，不制作
本周跟进块发出：__ 条（逐条检查是否带新东西）
本周止损：__ 单（写明真实理由）
```

A/B/C 的判定见 [58-client-grading-and-time.md](58-client-grading-and-time.md)，按行为信号分，不按金额、不给人贴标签。

## 六、隐私与信息边界

- 记录里不写姓名全名、公司名、联系方式、金额明细等可识别信息，用代号即可。
- 贴入的聊天记录若含第三方信息，只抽取与判断有关的事实。
- 记录只用于本单判断，不进入对外内容；想做成案例必须先取得授权并脱敏，见 [56-testimonials-and-authorization.md](56-testimonials-and-authorization.md)。
- Agent 不在会话之间保存这些记录；用户下次要复盘，需要重新贴入或明确确认。

## 七、常见错误

- 把推断写进事实栏，下次当成客户说过的话。
- 记成小作文，下次自己都不想看。
- 只记结果（「没成」），不记停在哪句。
- 记录里出现对客户的评价。
- 把同一张表发给客户看。

## 八、禁忌

最忌讳**用表格替代判断**。表是承载，真正决定下一步的仍是「他有没有说过自己的处境、有没有说过怎么定」。这两条没有，表填得再满也不该投入制作时间。
