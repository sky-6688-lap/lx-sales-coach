# 96 工作表：从零拼一条消息（填空模板）

> 补 [15-message-checklist.md](15-message-checklist.md)、[19-message-style-rewrites.md](19-message-style-rewrites.md)、[14-quick-answers.md](14-quick-answers.md)。前面给的是各场景的成品句，这一篇给**没有对应场景时，也能自己拼出一条能发的消息**的方法。所有示例均为**模板示例（非真实案例）**。

## 一、拼装公式：四格，不超过三条

任何场景都能拆成四格。填完四格，再删到只剩必要的。

```text
【1 接住】用他的词复述他上一句里的那一个点（不为寒暄）
【2 给一样东西】一个事实 / 一个判断 / 一份材料（只给一样）
【3 留口子】一个好回答的问题，或「不用回我」
【4 删】去掉解释、体谅、自证、铺垫、第二问
```

**短句连发**：一段拆成 3-5 条，单条不超过 3 行，说「咱们」、语气词用够、反问确认收尾。这是六条消息风格里的硬项，见 [19-message-style-rewrites.md](19-message-style-rewrites.md)、[15-message-checklist.md](15-message-checklist.md)。

## 二、按意图选骨架

同一个公式，意图不同，「给一样东西」那一格填的东西不同。

| 这一句要做的事 | 第 2 格填什么 | 骨架 |
|---|---|---|
| 把状态往前推一步 | 一个具体选项 | 接住 + 给 [选项] + 「你看行吗」 |
| 把价值说清 | 一句结果（用他的词） | 接住 + [他那句结果] + 「是这块吗」 |
| 把价格落地 | 一页里的价格与交付物 | 接住 + 一页已发 + 需要他定的一个点 |
| 接住异议 | 一句分类判断，不辩解 | 接住 + 「这块属于 [类型]」+ 一个选项 |
| 止损 / 留口子 | 不再投入的明确说明 | 接住 + 「先不排了」+ 「随时找我」 |
| 交付后同步 | 一个进度事实 | 接住 + [已做的事] + 下一个时间点 |

## 三、填空模板（直接复制）

```text
版本 A｜推进
> 你说的 [他的词] 我记着。下一步可以先 [一个动作]，[时间] 对一次，行吗？

版本 B｜确认价值
> 我理一下：你这轮要的是 [他的词里的结果]。先按这块对，是吗？

版本 C｜报价落地
> 一页发你了，[交付物] 和 [价格] 都在上面。需要你定的只有 [一项]。

版本 D｜接异议
> [他那句] 我看到了。这块属于 [类型]，给你两个选：[选项一] 或 [选项二]。

版本 E｜止损
> 那这轮先不排了，别占你时间。后面想重启随时找我，材料都留着。

版本 F｜交付同步
> [交付物] 已发你。下一步 [事项] 我按 [时间] 跟进，有变化随时说。
```

**`[占位]` 的规矩**：拿不到的信息一律留 `[占位]` 并在消息外说明，不替用户编产品名、价格、客户原话。用户说「别问了直接给」时走急救例外，见 [14-quick-answers.md](14-quick-answers.md)、[17-gate-playbook.md](17-gate-playbook.md)。

## 四、拼完必过的六格检查

| 检查 | 不合格的样子 | 改法 |
|---|---|---|
| 有没有接住他的词 | 「感谢您的关注」 | 换成他原话里的那一个词 |
| 是不是只给一样东西 | 一段里塞了观点 + 案例 + 链接 | 只留一样，其余删 |
| 有没有解释与自证 | 「其实我们做过很多……」 | 整句删 |
| 单条是否不超过 3 行 | 一句里三个逗号两个分号 | 拆成短句连发，别写一大段 |
| 结尾好不好回答 | 「您考虑一下」 | 换成具体选项或「不用回我」 |
| 有没有越界 | 保证结果、限时、群发感 | 过 [21-boundaries-and-compliance.md](21-boundaries-and-compliance.md) |

完整自检清单见 [15-message-checklist.md](15-message-checklist.md)，成套检查表见 [68-checklist-bundle.md](68-checklist-bundle.md)。

## 五、五组「改前 / 改后」

改写法是本技能最核心的手艺，更多对照见 [19-message-style-rewrites.md](19-message-style-rewrites.md)、[63-chat-script-library.md](63-chat-script-library.md)。

| 改前（念稿腔） | 改后（能发） |
|---|---|
| 您好，感谢您的咨询，我们这边可以提供全方位的解决方案 | > 你说的 [卡点] 我看到了，先对这一处？ |
| 不好意思打扰了，不知道您这边考虑得怎么样了 | > 上次那页还在，需要你定的只有 [一项]。 |
| 我们这个价格其实已经很优惠了，性价比非常高 | > 按 [数字] 的话我把 [某项] 拿掉，其余不变。 |
| 您放心，效果这块我们肯定能保证让您满意 | > 能确定的是给你 [交付物]，结果我不打包票。 |
| 最近比较忙可能回复不及时，还请多多理解 | > [交付物] 已发，下一步 [时间] 对一次。 |

**改后的共同点**：不复述礼貌、不解释自己、不承诺不可控的事、把下一句留给对方一个好回答的问题。

## 六、从四段式回答到一条消息

Agent 的完整回答是四段式（先说透认知 / 依据与风险 / 可直接发的消息 / 下一步与一条禁忌），见 [20-four-part-answer-examples.md](20-four-part-answer-examples.md)。但**用户真正要发出去的只有第三段**。所以：

- 第三段必须能独立成立，脱离前面两段也读得懂、发得出去。
- 不要在第三段里写「如上面所说」「根据前面的判断」这类依赖上下文的话。
- 用户说「简单说」时，四段式可以只给第 1、3 段，但第 3 段不能省，见 [20-four-part-answer-examples.md](20-four-part-answer-examples.md)。

## 七、禁忌

1. 不用「您好 / 感谢咨询 / 打扰了 / 多多理解」当开头，见 [19-message-style-rewrites.md](19-message-style-rewrites.md)。
2. 不一条里塞两个问题，不写「您看什么时候方便」这种把成本推给对方的收尾。
3. 不编产品、价格、客户原话、案例数据；缺信息就用 `[占位]`，不硬凑。
4. 不写保证结果、限时稀缺、制造抢购感；不夹带外部课程或专栏链接。
5. 不一次给十条同质消息，不把整篇模板甩给用户，见 [61-content-templates.md](61-content-templates.md)。
