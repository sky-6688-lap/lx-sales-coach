# 35 价格异议二：不确定值不值

> 05 的第二分支，与 [39-trust-and-guarantees.md](39-trust-and-guarantees.md) 相邻。判断依据：他问「做完能到什么程度」「万一没用呢」，或反复确认包含什么，但没提预算上限。

## 一、这一类的「贵」不是钱的问题

他在问：**我付这笔，究竟会拿到什么、有多少取决于我、做不成算谁的**。此时降价没用——降完他仍在犹豫，因为不确定的东西一样没变。甚至会更犹豫：价格忽然能降，会让人怀疑原价不实。

有效动作只有两个：**把可核对的部分说清**，**把第一次变小**。

## 二、可核对的四块

| 块 | 写什么 | 别写 |
|---|---|---|
| 交付物 | 具体形态、几份、能不能改 | 「一套方法」「完整支持」 |
| 过程 | 几次、每次做什么、多久 | 「全程陪伴」 |
| 你的配合项 | 需要他给什么、花多少时间 | 「配合一下就行」 |
| 不确定的部分 | 哪块取决于他的投入、哪块取决于外部 | 把不确定性全抹掉 |

第四块最反直觉，但最有用。明说「这部分不到位，进度会受影响」，比「放心交给我」更能让人判断。

## 三、标准接法（三段）

> 这个我不说包结果的话，先把会拿到什么说清楚。
> 做完你会有一份 [交付物]；中间 [具体动作]；需要你配合的是 [材料 / 时间]，这部分不到位进度会受影响。
> 要不先按 [更小的第一步] 试一次，做完你看东西再决定要不要往下走？

**「先按小第一步」是这一类的核心动作**：把「信不信我」换成「用一次小范围核对」。不需要任何案例、保证或数据。

## 四、八种说法与接法

| 他说 | 背后在问 | 一句接法 |
|---|---|---|
| 「做完能到什么程度」 | 交付物形态 | 「做完你会拿到 [具体东西]，不是口头建议」 |
| 「万一没用呢」 | 风险与边界 | 「我不说保证的话；能确定的是 [交付物] 和 [动作]」 |
| 「包含几次啊」 | 过程是否清楚 | 「[次数] 次，每次 [做什么]，中间给你 [东西]」 |
| 「我自己要做很多吗」 | 配合成本 | 「你这边只要 [材料] 和 [时间]」 |
| 「别人说做了没变化」 | 可核对性 | 「我不评价别家，先按你的情况对一遍范围」 |
| 「能不能先看看效果」 | 想零成本验证 | 给小第一步，不给成品方案 |
| 「你这个跟自己弄差在哪」 | 替代成本 | 「自己弄通常卡在 [他提过的那一步]；这轮就处理这一步」 |
| 「有没有做过我这种」 | 相邻经验 | 转 39，如实说边界 |

## 五、和信任类的分界

| 落在 35 | 落在 39 |
|---|---|
| 问交付物、包含项、配合项 | 问保证、案例、资质、做过没有 |
| 要的是「东西是什么」 | 要的是「你这个人靠不靠谱」 |
| 动作：说清范围 + 小第一步 | 动作：如实说边界 + 可核对事实 |

两类常一起出现。主状态取**先问出来的那个**；若他先问「万一没效果」再问「包含什么」，按 39 主、35 辅，但只输出一版消息，把交付物并进去。

## 六、常见错误

- 用「效果看得见」「客户都说好」这类无法核对的话。
- 主动降价来消除不确定（越降越像心虚）。
- 发一大段案例与好评压过去。
- 把不确定的部分全藏起来，交付期再解释。
- 承诺「不满意退」，但用户根本没定过这条规则。

## 七、禁忌

最忌讳**为了让人放心把话说满**。一句「肯定没问题」换来的短期安心，会在交付期变成更大的矛盾——而这个 Skill 的每条消息都要经得起用户真的发出去。
