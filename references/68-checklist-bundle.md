# 68 八张可直接用的检查表

> 把散落在各篇的自检集中成可勾选的清单。打印或复制到笔记里用，不要求 Agent 持久化任何内容。

---

## 表 1｜报价前

- [ ] 三个可以报的信号，满足了两个吗？（25）
- [ ] 需求确认句说过、对方认可了吗？（03）
- [ ] 报价三件套齐了吗：做什么 / 交付什么 / 下一步？
- [ ] 写了不包含什么？
- [ ] 需要对方配合什么，写清了吗？
- [ ] 价格带确认了吗（百元 / 千元 / 万元以上）？
- [ ] 有没有出现保证、一定、包过等承诺？

## 表 2｜发消息前（12 条，同 15）

- [ ] 门禁四项齐了？不齐走占位版
- [ ] 状态判的是对方那头发生的事？
- [ ] 每条只做一件事、连发 ≤3 条？
- [ ] 能直接复制，没有旁白与指令？
- [ ] 用了客户原词？
- [ ] 占位符都替换或标注了？
- [ ] 结尾是好回答的口子？
- [ ] 没有道歉铺垫、连环追问、感叹号？
- [ ] 单条以 60 字内为主？
- [ ] 没有限时、名额、涨价预告、替客户做决定？
- [ ] 没有保证、编造的案例或数字？
- [ ] 合规与归属过了一遍？

## 表 3｜一页提案发出前（同 26）

- [ ] 第 1 块用了对方原话
- [ ] 交付物有形态
- [ ] 时间具体
- [ ] 写了配合项
- [ ] 写了不包含
- [ ] 修改轮次有数字
- [ ] 决策人 / 对接人明确
- [ ] 价格与范围绑定
- [ ] 付款方式只写确认过的
- [ ] 下一步能回答是或否
- [ ] 没有承诺与夸大
- [ ] 没有第三方信息与外部链接

## 表 4｜收定金前（同 49）

- [ ] 金额或比例
- [ ] 抵不抵、怎么抵
- [ ] 可退 / 不可退情形（按用户真实规则）
- [ ] 付了之后下一步是什么
- [ ] 规则都是用户自己定的，没有 Agent 代编
- [ ] 没有「定金不退」施压、没有限时

## 表 5｜收款后 / 交付开始前（同 50）

- [ ] 第一句给了时间、动作、配合项
- [ ] 材料清单 ≤5 行，需准备的 ≤2 项
- [ ] 边界提醒（若有）在开始前说了
- [ ] 没有立刻推复购 / 转介绍
- [ ] 没有临时加赠

## 表 6｜跟进发出前（同 41、30）

- [ ] 上次停在哪句（原话）
- [ ] 已经给过什么（不重复）
- [ ] 这一条的新东西是什么
- [ ] 真实由头可核对吗
- [ ] 没有要求对方解释为什么没回
- [ ] 三次触达用完了吗（用完 → 止损）

## 表 7｜每周复盘（同 31、58）

- [ ] 只挑一单，不盘全部
- [ ] 事实与推断分栏
- [ ] 断点只定一个
- [ ] 引用了记录里的原话
- [ ] 写明了「记录里看不出的部分」
- [ ] 下周只改一处
- [ ] 没有评价客户或用户

## 表 8｜内容发布前（同 61）

- [ ] 发布场景、目标读者、禁用表述确认过
- [ ] 每条只解决一件事
- [ ] 取材来源标注了，无来源的标「需补真实素材」
- [ ] 授权范围核对过（56）
- [ ] 脱敏完成
- [ ] 没有编案例、数字、前后对比
- [ ] 没有限时、名额、涨价预告
- [ ] 没有外部链接、承接模块、第三方名称
- [ ] 结尾是具体口子，不是「欢迎咨询」

---

## 使用方式

一次只用一张，别八张全过。报价前用表 1，临发消息用表 2，周复盘用表 7。**清单是防漏工具，不是判断替代品**：真正决定该不该发、该发什么的，仍是状态判定与用户提供的原话。

## 常见错误

- 表勾完了，但消息里仍有一个没替换的占位符。
- 把清单发给客户看。
- 为了勾满而补信息（例如硬凑「不包含」却写「其他双方协商」）。
- 一次过八张，结果一张也没细看。

## 禁忌

最忌讳**用形式完整掩盖判断缺失**。八张全勾、状态判错，消息照样发不出去；先判状态，再过清单。
