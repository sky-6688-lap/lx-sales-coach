# 42 跟进节奏矩阵：三档价格 × 四种情况

> 补 [08-follow-up-rhythm.md](08-follow-up-rhythm.md) 的节奏表。数字是起点，不是闹钟；用户给过时间就按用户的来。

## 一、主矩阵

| 情况 | 第一次 | 第二次 | 第三次 | 之后 |
|---|---|---|---|---|
| 百元级 / 轻决策 | 2–3 天 | 5–7 天 | 不再主动 | 等对方回来 |
| 千元级 / 已报价 | 3–4 天 | 7 天左右 | 14 天左右 | 收尾一次，转低频 |
| 万元以上 / 需共同决策 | 4–7 天 | 按他说的决策节点 | 节点后一次 | 只在有真实变化时出现 |
| 说了「过阵子 / 下个月」 | 按他给的时间点 | — | — | 不提前打扰 |

## 二、按最后反应调整

| 对方最后的反应 | 调整 |
|---|---|
| 每次都有回，只是没定 | 按对话节奏走，不套表 |
| 回复越来越短（两句 → 一个字） | 间隔拉长一倍，内容再轻一点 |
| 明确给了时间点 | 那个时间之前不出现，出现时第一句就提这个由头 |
| 明确说「暂时不需要」 | 停止主动跟进，见 44 |
| 三次触点后无实质回复 | 止损，不再有第四次 |
| 他主动回来问了一句 | 立即按新消息判状态，不再按排期 |

**「实质回复」的定义**：回答了那个具体小问题、给了新信息、问了交付或时间。只回表情、嗯、好的、收到，都算无实质。

## 三、三档价格带的力度差异

| 档 | 跟进里适合带什么 | 不适合 |
|---|---|---|
| 百元级 | 一个更轻的入口、一条有用信息 | 提案、多轮诊断、三次以上触达 |
| 千元级 | 范围选项、交付物说明、他问过的问题的答案 | 反复问「考虑得怎么样」 |
| 万元以上 | 一页范围、分阶段第一步、决策人用得上的材料 | 用几条消息催决定、用折扣换推进 |

价格带由用户在门禁里提供，不按行业猜。

## 四、四种特殊情况

1. **共同决策**：间隔按对方说的决策节点走。节点前发材料可以，节点前催决定不行。
2. **交付期中的老客**：不适用追单节奏，按 [52-delivery-checkpoints.md](52-delivery-checkpoints.md) 的节点出现。
3. **内容带来的新咨询**：第一次回复要快，但内容仍是接住他的具体处境，不是立刻报价。
4. **多单并行**：同一周不要给两个客户发同一段跟进；由头与内容按各自记录生成（见 58）。

## 五、排期怎么落进时间块

把跟进集中到每周 1–2 个「跟进块」处理，而不是随时想起随时发：

```
跟进块开始 → 打开跟进三格 → 逐单问「有无新东西」
           → 有：按矩阵发；没有：标「等由头」，不凑数
           → 记录本次发了什么，避免下次重复
```

这张表配合 [58-client-grading-and-time.md](58-client-grading-and-time.md) 的三块时间用；A 类优先占谈单块，C 类统一在跟进块回一两句。

## 六、常见错误

- 把矩阵当成群发排期表，到点就发。
- 对方说「月底再看」，你按 D+3 发一条。
- 用节日问候填补没有由头的空白。
- 三次之后再来「最后一次」。
- 把「他没回」记成「他拒绝」，从此不再出现，也没留真实由头。

## 七、禁忌

最忌讳**用固定间隔覆盖真实事件**。他提过的节点、他做过的事有新进展、你这边范围真的变了——这三类真实由头永远优先于表里的天数。
